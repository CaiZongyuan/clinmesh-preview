# 从 ClinMesh 到全球 Mini HIS：范围与模块决策建议

**定位假设**：给单个基层门诊或有少量普通病床的综合医疗机构使用；首版先做门诊，再按需启用住院。不以三甲医院全科室、多院区集团或全球保险理赔为目标。“全球通用”的检验标准是：换机构、语言、支付制度时，不必改写患者身份、就诊、医嘱和记录的核心逻辑。它不是“零配置即可在各国合法上线”的承诺。

本文是目标建议。已导入平台的模型仍表示 [ClinMesh 现状](README.md)，不是下列能力的实现声明。以下“待补”指未见足以覆盖目标场景的端到端证据，不等于仓库完全没有相关类型或草稿。

外部对照见[五个开源项目：哪些经验值得移植](open-source-benchmarks.md)。据此建议把**版本化机构配置包、离诊后的结果责任队列、不依赖公网的院内接诊**列入首版验收；是否支持多终端断线写入与自动合并则另行决策。

## 1. 留下什么，搬出什么

| 现状切片 | 决策 | 目标归属与原因 |
| --- | --- | --- |
| 本院患者、一次就诊、责任人、正式诊断、申请、报告修订、签署文书 | 保留 | 临床核心。明确谁在何时对哪个版本负责；患者自述、建议、草稿均不能当作正式事实。 |
| 开立、发药、实际给药；应收、收款、待遇；离区、床位、财务、归档 | 保留区分，不保留全球固定办理顺序 | 已发药不是已给药，退款不能改写诊疗，这是不变量；先付款再检查、先结算再清床是可变政策。 |
| 完诊七项门禁、十岗位、固定就诊号、虚拟上海午夜按床日计费 | 改为机构政策或地区配置 | 核心保留责任交接与证据，机构配置有版本的完诊清单、岗位授权、号码签发与计费日历。不能仅翻译岗位名，更不能给所有人开通全部动作。 |
| 中国医保甲乙丙、年度待遇、CHS-DRG、特定病案首页和编码摘录 | 下沉到地区／支付方模块 | 不删除已有投资；原规则可以服务中国仿真配置，但不能当作全球默认或中国真实医保接口。基本账务无需知道病组。 |
| PCI 耗材预估、冠脉选型、病理切片会诊、专病评分和 AI 指南 | 下沉到专科模块；首版不装 | 通用申请、实际操作、结果和来源更正可复用；策略、专科素材和模型依赖不要进入普通接诊路径。 |
| 病例真值、角色稿、虚拟时钟、Epoch、重放 | 限教学／验证部署 | 真实患者不应先有合成病例才能挂号；生产环境不注册重置和模拟回报入口。保留真实业务发生时间、录入时间、事件追溯与审计，不保留“重置病历”的能力。 |
| DSH、宿主、开发工具；完整 ERP、PACS、ICU、输血 | 不进入首版 | 前者不是 HIS 业务，后者是独立产品或高风险专科；有明确需求时用接口对接，不建通用插件市场。 |

## 2. 按试点优先级补缺

| 优先级／能力 | 已有起点 → 要补的最小闭环 | 一个能判定完成的例子 |
| --- | --- | --- |
| P0 患者身份与连续病历 | 已有 Patient 与多次就诊；补多签发方标识、无证件临时登记、别名与重复候选、人工合并和误并纠错；建立跨就诊问题、过敏、用药及来源维护 | 两个同名患者不自动合并；临时身份转正不丢原就诊；过敏“尚未询问”不显示为“无已知过敏”。 |
| P0 实际接诊与后续责任 | 已有现场候诊、签署、已阅；补不依赖仿真问答的直接接诊、异常中止、离诊后未回结果的责任队列、转诊／随访交接 | 病人先离开，外送结果次日才回；结果落到原申请与负责人，换班能转交，更正能重新通知，不为接收结果虚造第二次就诊。 |
| P0 本地化与机构主数据 | 已有双语及版本化目录；补机构时区、姓名地址与标识、币种及小数位、计量单位、术语体系／版本、药品和检验本院目录映射；专业内容翻译与界面翻译分治 | 两家机构使用不同币种和本地项目码；升级目录后仍能按当时的码、单位与价格解释旧记录。金额不统一假设为“分”。 |
| P0 基本资金（收费机构） | 已有预览、收退与关联原款；抽出价目、逐项应收、实收、冲退、收据及日结对账；允许无现场收费或延期结账。理赔另算 | 一家免费接诊、不启用收费，另一家自费且分次付款；两家走同一临床流程。支付结果未知不能重复扣款。 |
| P0 真实患者试点前置条件 | 已有受信岗位、版本、审计及备份机制；另验生产身份管理、授权与撤权、敏感记录访问审计、代理／监护与同意策略、保留／导出、加密与密钥运维、停机登记／补录、备份恢复演练 | 被撤权人员不能继续读病历；停机补录保留实际发生人和发生时间；从备份恢复后核对患者、医嘱与账目。各地由当地临床、隐私和合规负责人确认适用要求。 |
| P1 按机构选装 | 预约型门诊补排班、号源、预约、到诊、取消和爽约；院内药房补收货入库、批次效期、退回与盘点（已有批次发放）；开住院则补可配置交班、出院摘要与用药核对 | 取消预约不产生挂号费；外配处方不动院内库存；已离院但欠费，按机构政策可释放床位，应收和未回报告仍可追踪。 |
| P1 对接（若首站依赖则升 P0） | 已有只读 FHIR R5 和仿真执行者；真实部署需按对方支持的版本／实施规范映射，有标识匹配、去重、错误队列和人工核对 | 同一外部结果发两次只产生一条结果；患者或申请无法唯一匹配时不得自动入病历。没有 LIS 的门诊可由授权人员明确录入外院结果并注明来源。 |

若首站接收急诊，不要把普通门诊换名交付；未识别患者、急诊分级、先救治与事后补登记、留观／转运是另一个需要验收的模块。若产品只用于教学，生产合规工作不冒充已完成项，仿真包也不必从教学发行版删除。

## 3. 模块化单体怎么切

ClinMesh **已采用模块化单体**（`docs/architecture/system.md`）。无需再引入一套框架。保持一个部署单元、进程内调用、初期一个业务库，按“谁有权修改哪项事实”分模块，而不是按页面、岗位、FHIR 资源或国家拆服务。

| 模块及装配 | 唯一拥有的业务事实 | 给其他模块的窄接口（建议，不是现有端点） |
| --- | --- | --- |
| 患者登记、机构与授权（核心内两个模块） | 前者拥有患者身份及标识关联；后者拥有机构、人员、受信岗位与服务范围 | 查找／登记／核对患者；判定某人在某机构能否对当前患者执行动作 |
| 就诊与临床记录（核心） | 就诊责任与交接；已确认临床问题、过敏、结构化记录与签署修订 | 开始／结束接诊、转交责任、签署／更正文书；不让收费模块写就诊状态 |
| 医嘱与结果（核心） | 请求意图、完成／取消、报告版本、已阅及待处理责任 | 开立、接收可追溯结果、确认已阅；无药房和 LIS 也能工作 |
| 预约、药房、住院、基础账务（分别选装） | 分别拥有号源承诺；批次与发放；住院及床位占用；应收与原款收退 | 预约转到诊、按处方发放、分床／释放、记费／收退；只有住院启用时才引入病区给药执行 |
| 地区与支付方、专科、外部对接、教学（扩展） | 分别拥有政策与映射版本、专科资料、外部消息关联、合成场景 | 地区包给出政策决定及版本，不代写临床或资金；外部系统经适配器走相同的正式业务命令；教学环境走正常临床入口 |

**以“出区后欠费”为接口检验。** 住院模块拥有实际出区和床位释放；账务拥有未结金额；机构政策决定当前是否允许释放。若需核对资金状态，由单体内公开查询在同一业务事务核对关键前提，任何一方不得直接更新对方表。释放不掩盖欠费；换成免费机构也无需制造一笔零元支付。审计、幂等、预期版本是共用能力，不是把所有领域数据交给一个“公共服务”。跨模块通知和对外消息可用提交后投递、去重与重试；涉及病历或资金的不变量不依赖异步通知碰巧按顺序到达。

**装配约束**：依赖方向是「扩展 → 业务模块 → 核心接口」，核心不读取“中国医保是否安装”这样的开关。启动时校验机构启用的功能、目录和政策；切换政策只对其生效日以后的适用业务生效，历史保留计算依据。在途申请或未清账时不允许直接卸载其模块，停用新业务后仍可查历史和完成交接。已经存在的角色与文书审计不能因为关掉支付或仿真而消失。

## 4. 实施顺序与验收

1. **先证明能脱离仿真**：同一代码部署为“无床、无药房、无现场收费”的步入式门诊。人工登记 → 接诊 → 诊断／记录 → 外配处方或无需用药 → 结束接诊；全程不创建病例真值、模拟资金或床位。同时走通未回结果追踪。
2. **再证明能换制度**：第二套虚构配置使用不同语言、时区、金额精度和目录，启用自费与院内药房；同一临床路径只多出应收和实际发放。若核心还判断国家名，或换政策后旧账改变，说明模块没有切开。
3. **最后增加病床和地区包**：带床小医院实测入院 → 占床 → 医嘱／执行 → 出区；验证欠费离院、未回报告和归档后更正。再按首个真实客户选择一个地区包和一个真实对接方；当地验收之前只标为仿真或试验功能。
