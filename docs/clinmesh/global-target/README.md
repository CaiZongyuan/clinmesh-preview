# 全球 Mini HIS · 目标业务模型

本地工作台项目 **全球 Mini HIS 目标业务模型**；结构化入口：[11 份模型](model/manifest.json)。这是从 [ClinMesh 现状](../README.md) 和[五个开源项目的对照](../open-source-benchmarks.md)提炼的目标，不是将仿真 HIS 的所有能力重新标为已实现。平台里两者是独立项目。

## 从哪几个对象开始看

| 从业务视图打开 | 要核对的问题 |
| --- | --- |
| 患者主档 → 身份核对单 → 一次来院／岗位接触 | 无证件可以就诊。同名不是同一人；误并后要保留逆向决定，并复核期间新增记录的归属。一次来院可以有多次护士或医生接触。 |
| 医技申请 → 正式结果修订 → 后续行动责任单 | 患者离开后，原申请仍有人负责。报告更正需重新阅知；医生要求复查时，须另外记录承接人、期限和实际处理结果。 |
| 机构业务配置版本 → 预约／药房／住院／账务 | 四项按机构分别选装。地区目录、保险理赔、专科规则各有版本，不把特定国家或支付方写进临床核心。模块停办新业务不得截断旧业务。 |

## 两个同地区机构的走查脚本（目标验收，非运行证明）

| 条件 | 预期业务结果 | 模型入口 |
| --- | --- | --- |
| 甲：免费现场门诊、无病床、无药房、检验外送。公网中断但院内系统与授权可用 | 临时登记 → 岗位接触 → 本地签署 → 离诊；不创建床位、零元收据或仿真病例。恢复连接后外部回报按原申请核对 | M6 `Clinic`、`Incoming`；M3 `local`、`document`、`match` |
| 甲：迟到回报有同名候选，随后来源方又更正结果 | 无法唯一匹配时留在待核清单；同一来源结果同版重送不重复入档。新版重阅；需要复查才另建行动单，已阅不等于复查办完 | M4 `LateResult`、`Correction`；M7 待核回报、未回与待阅、未结后续行动三份清单 |
| 乙：同地区，启用预约、院内药房、住院及自费；政策允许欠费离院后释放床位 | 预约取消不算到诊；实际发药才出库；患者离院后可依政策释放原床，原逐项应收不消失。支付回执未知应恢复原尝试 | M6 `Ward`；M3 `appointment`、`stock`、`bed`、`money` |

**范围**：本版定义核心与四个选装模块的业务合同；MM 为候选逻辑表，MI 为拟议合同，不代表已有物理表或在线端点。真实上线前仍需当地验证隐私同意与保留政策、停机补录与灾备、临床安全和外部对接。没有引入 DSH、仿真重置、DRG、PCI 或完整 ERP 作为全球必装能力。

校验：在 ontology-plus 根目录运行 `pnpm exec tsx docs/extractions/clinmesh/validate.ts target`；不带参数则验证 ClinMesh 现状。校验覆盖格式、交叉引用、核心对象不依赖选装对象、无收费门诊及外送结果流程不调用选装模块。
