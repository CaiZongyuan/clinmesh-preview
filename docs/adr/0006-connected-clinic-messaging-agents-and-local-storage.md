# Connected Clinic Messaging, Agent Services, Follow-up Lifecycle, and Local Attachment Storage

To deliver slices S2–S8 of Issue #45 (`ClinMesh Connected Clinic`) on top of the existing single-runtime Cloudflare Worker + `ClinicWorkspaceDO` SQLite architecture without premature infrastructure sprawl, we extend the workspace schema with append-only migrations and add two dedicated Durable Object agents reusing `src/worker/durable-agent/`.

## Key Decisions

- **Authoritative transactional appointments & releases**: `AppointmentRepository` checks slot status, duplicate active patient-slot bookings, and slot capacity inside a single `ClinicWorkspaceDO` SQLite transaction, keyed by `UNIQUE (patient_id, client_request_id)`. Starting an Encounter from an appointment preserves the single-active-encounter invariant and never mutates or consumes an appointment if `encounters.start` fails. `PatientReleaseRepository` publishes only signed Clinical Note revisions, released non-cancelled Reports, or formal Prescriptions/No-Medication records, and supports explicit retraction.
- **WuKongIM v2.2.5 transport with HIS-owned reliability**: `CommunicationRepository` owns canonical membership, `conversation_member.last_read_seq` (single authority for read cursors), and `send_command` keyed by `UNIQUE (conversation_id, client_message_id)`. On uncertain or failed delivery, retries first reconcile via WuKongIM `POST /channel/messagesync` before dispatching `POST /message/send`, preventing duplicate sequence entries despite WuKongIM v2.2.5 not deduplicating repeated `client_msg_no`. 64-bit `message_id` fields are extracted from raw JSON strings before `JSON.parse`. Logout rotates the actor's IM token and invokes `/user/device_quit`.
- **Local-first attachment storage seam**: For local development and test repeatability without requiring external cloud object storage provisioning, `AttachmentRepository` persists validated binary blobs (`<= 5 MiB`, MIME allowlist, audio duration `<= 60s`, SHA-256 hash) in `attachment_blob` behind the exact `init -> upload -> complete -> short-lived HMAC signed access URL` HTTP contract. Uncompleted attachments cannot be referenced in messages; expired signed URLs return `403 attachment-expired`. ASR transcription stays optional and honest (`unavailable` / `none` when no async ASR job runs; transcripts are never fabricated).
- **Scoped Durable Agents (`PatientServiceAgentDO` and `FollowUpAgentDO`)**: Both extend `DurableAgentRuntime` (`streamThinking: false`, `traceSteps: true`), bound strictly by session key (`clinicId:patientActorId` and `conversationId:actor_agent_followup`). `PatientServiceAgentDO` has no arbitrary `patientId` parameter and no formal clinical write tools; client navigation actions (`medical.record.open`, `appointment.open`) are bound to `(actorId, sessionId, runId, callId, TTL)` and validated against the MiniProgram route whitelist. `FollowUpAgentDO` re-checks conversation status and membership on every step/tool/settlement, only responds to explicit human `@mention` triggers (ignoring agent/system messages), never exposes private patient medical records in group chats, and creates `draft` summaries requiring doctor approval.
- **Local LLM default**: Local development uses `zhipu/glm-5.3-flash` with `LLM_REASONING_EFFORT=off` and `LLM_EFFORT_STYLE=zhipu` (`thinking: { type: 'disabled' }`), while automated Worker tests pin `CLINIC_MODE=simulation`, `WUKONGIM_MODE=fake`, and `LLM_PROVIDER=scripted` in `vitest.config.ts` so `.dev.vars` never breaks deterministic regression suites.
